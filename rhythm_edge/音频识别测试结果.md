# 韵律识别音频测试结果

测试对象为 `rhythm_train` 中的 `1.wav` 至 `5.wav`。`choice.wav` 为约 106 秒，按当前约 15 秒的建库规则跳过。本轮没有使用扬声器和麦克风录音。

识别门限：最高相关分数至少 0.45，且比第二名高至少 0.10。下表每格为“是否识别正确 / 最高分”。

| 输入条件 | 1.wav | 2.wav | 3.wav | 4.wav | 5.wav |
|---|---:|---:|---:|---:|---:|
| 原始 WAV | 对 / 1.000 | 对 / 1.000 | 对 / 1.000 | 对 / 1.000 | 对 / 1.000 |
| 起始延迟 0.5 秒、音量降低、15 dB 噪声 | 对 / 0.818 | 对 / 0.939 | 对 / 0.876 | 对 / 0.880 | 对 / 0.852 |
| 播放速度加快 2% | 对 / 0.563 | 对 / 0.587 | 对 / 0.632 | 对 / 0.593 | 对 / 0.578 |
| 播放速度减慢 2% | 对 / 0.488 | 对 / 0.559 | 对 / 0.631 | 对 / 0.554 | 对 / 0.550 |
| 250 至 3200 Hz 限带、70 ms 回声、25 dB 噪声 | 对 / 0.686 | 对 / 0.759 | 对 / 0.684 | 对 / 0.673 | 对 / 0.699 |

合计 **25/25** 次正确。把待测类别临时从特征库中移除后，五段音频均返回未识别，说明在这组音频上没有被强行归入其余类别。

需要注意两个边界：`1.wav` 减速 2% 时分数为 0.488，离 0.45 的门限较近；`4.wav` 减速 2% 时第一名与第二名差距为 0.122，离 0.10 的门限也较近。实际扬声器、房间和麦克风可能进一步降低分数，应以机器人现场录音重新核对门限。

原始逐条结果及各类别分数见 `evaluation_results.json`。这些测试都由建库音频本身变换得到，只证明当前程序在这组输入下的行为，不能作为真实场景识别率。
